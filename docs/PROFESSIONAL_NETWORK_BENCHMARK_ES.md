# HELPMAN — Fase 3: Benchmark de red profesional

## Referencias analizadas

### Taskrabbit
- Onboarding con requisitos de identidad/background check.
- Cuenta bancaria para cobrar.
- El profesional administra trabajos desde una experiencia dedicada.
- La elegibilidad depende de ciudad/mercado activo.

### Thumbtack
- Herramientas para crecer el negocio.
- Perfil del profesional y reputación.
- Visibilidad del potencial de ingresos.
- El valor para el pro no debe limitarse a “recibir leads”.

### Houzz Pro
- Dashboard específico para contratistas/subcontratistas.
- Schedules, tareas, fotos, archivos y daily logs.
- Seguimiento de montos pagados/pendientes.
- Colaboración operacional dentro del proyecto.
- Permisos diferenciados para no exponer información financiera sensible.

## Diseño HELPMAN

HELPMAN adopta lo mejor de estas referencias, pero conserva un modelo administrado:

Apply → Verify → Activate → Set skills & availability → Receive offer → Accept/decline →
Execute → Daily log → Milestones → Quality review → Payout → Score improvement

## Diferenciadores HELPMAN

1. Professional Readiness
   No basta con crear cuenta: el sistema muestra exactamente qué falta para estar listo.

2. Skill Matrix
   Las especialidades dejan de ser un string suelto. Se modelan por skill, nivel y años.

3. Availability
   El matching no debe recomendar a un profesional que no está disponible.

4. Compliance Center
   Licencia, seguro, background y documentos tienen estado y expiración.

5. Explainable Matching
   El profesional puede entender por qué recibió una oferta; administración puede entender por qué fue recomendado.

6. Offer Discipline
   Se mide aceptación, declinación, expiración y velocidad de respuesta.

7. Field Operations
   Daily logs, fotos y milestones forman evidencia del trabajo.

8. Payout Visibility
   El profesional ve cuánto está pendiente, aprobado y pagado sin ver el margen interno completo.

9. Professional Score
   Score compuesto y explicable, nunca una cifra opaca o puramente “AI”.

10. Retention
   La plataforma puede detectar buenos profesionales inactivos y problemas de desempeño antes de perder calidad de red.

## Lo que HELPMAN no debe hacer
- vender leads sin contexto;
- mostrar datos sensibles del cliente antes de aceptar un trabajo si no es necesario;
- prometer licencias/verificaciones no completadas;
- usar un score opaco para suspender automáticamente;
- mezclar datos del margen interno con el dashboard del contratista;
- permitir que un documento vencido siga figurando como verificado.
